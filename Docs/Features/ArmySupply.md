# 방어전 병력 보급

상태: 구현·검증 완료. 브랜치 `codex/army-supply`, 기준 main `e716ac7`.

## 규칙

침공이 시작될 때 살아 있는 아군(영주 포함) 1명당 식량 1을 지급합니다. 보유 식량이 부족해도 침공은 진행하며, 남은 식량만 사용합니다. 훈련 취소를 위해 보관한 식량은 사용하지 않습니다.

배급을 전부 받으면 공격력 100%, 하나도 받지 못하면 기본 75%이며 부분 배급은 그 사이를 비례 계산합니다. 배급 비율은 해당 방어전 동안 고정하고, 최종 타격 피해는 정수 내림·최소 1입니다. 적의 피해에는 영향을 주지 않습니다. 다음 준비 및 종료 상태에서는 공격력이 정상으로 돌아옵니다.

준비 화면의 ARMY SUPPLY가 다음 방어에 필요한 식량, 보유량, 예상 공격력 비율을 표시합니다. 전투 중에는 실제 지급량과 확정 비율을 표시합니다. 따라서 농장을 만들고 충원용 식량과 전투용 식량을 나누어 준비해야 합니다.

## 설계 결정

원본 기획은 식량 부담과 원정 보급을 요구하지만 초기 방어전의 구체적인 소비 시점·수치는 정하지 않았습니다. 현재 단계에서는 방어전당 한 번 소비하는 규칙을 선택했습니다. 적의 침공 자체가 플레이어 식량 부족 때문에 멈추지 않도록 했습니다. 일일 주민 소비·운송 경로·원정 포탈 수송은 후속 시스템입니다.

`ArmySupplySettings`가 비용·공격력 계산, `ArmySupply`가 차수별 배급 상태, `PortalInvasion`이 침공 시작 시점과 초기/충원 병력의 연결, `UnitCombat`이 실제 타격 피해 적용을 담당합니다. 공급 컴포넌트가 없는 기존 씬은 공격력 100%를 유지합니다. 병력 수를 매번 검색하지 않고 기존 방어 병력 명부를 사용하며, 화면의 준비 병력 변동 확인은 0.25초 간격입니다.

배급 상태와 시작 상태를 자원 변경 알림 전에 확정해 시작 버튼 반복 호출이나 자원 알림 재진입이 식량을 이중 소비하지 않게 합니다. 전투 중 설정 에셋을 바꾸거나 병력이 죽어도 현재 배급을 다시 계산하지 않습니다. 비활성화 후 재활성화는 추가 지급 없이 기존 배급 상태를 사용합니다. 재시작은 모든 배급 상태를 초기화합니다.
